DBImport collects detailed statistics for every import and export operation and makes them available in three ways: database tables (always active), a REST endpoint, and a Kafka endpoint. The REST and Kafka outputs emit structured JSON that downstream systems — dashboards, alerting tools, data pipelines — can consume in real time to react to completed operations or monitor overall system health.

## Database Tables

Statistical records are written to the DBImport configuration database automatically, with no additional setup required. Four tables are available:

| Table | Contents |
|---|---|
| `import_statistics` | Full history of all import runs. |
| `import_statistics_last` | Only the most recent run for each imported table. |
| `export_statistics` | Full history of all export runs. |
| `export_statistics_last` | Only the most recent run for each exported table. |

The `_last` tables exist as a performance convenience: querying them avoids scanning the full history table when you only care about the current state of each table.

## JSON Statistics Format

Two JSON formats are available for the REST and Kafka outputs. They can be selected independently per endpoint — for example, you can send the default format to Kafka and the extended format to REST.

## Airflow DAG Events

In addition to per-table statistics, DBImport can emit a JSON event when an Airflow DAG starts and when it finishes. Enable this by setting `post_airflow_dag_operations` to `1` in the `configuration` table. Events are sent to whichever endpoints (REST, Kafka) are currently enabled.

<CardGroup cols={2}>
  <Card title="DAG Started" icon="play">
    Emitted by the `start` task after confirming execution is allowed.

    ```json
    {
        "type": "airflow_dag",
        "status": "started",
        "dag": "<name of dag>"
    }
    ```
  </Card>
  <Card title="DAG Finished" icon="flag-checkered">
    Emitted by the `stop` task at the end of the DAG.

    ```json
    {
        "type": "airflow_dag",
        "status": "finished",
        "dag": "<name of dag>"
    }
    ```
  </Card>
</CardGroup>

## Enabling Outputs

All output configuration lives in the `configuration` table under keys prefixed with `post_`:

### REST Endpoint

| Configuration Key | Type | Description |
|---|---|---|
| `post_data_to_rest` | `valueInt` | Set to `1` to enable the REST endpoint. |
| `post_data_to_rest_extended` | `valueInt` | Set to `1` to send extended statistics to REST instead of the default format. |
| `rest_url` | `valueStr` | Full URL of the REST endpoint. |
| `rest_verifyssl` | `valueInt` | Set to `1` to verify the server's SSL certificate. |
| `rest_trustcafile` | `valueStr` | Path to a CA bundle file for SSL verification. |
| `rest_timeout` | `valueInt` | Timeout in seconds for REST calls. |

<Tip>
  A popular way to stand up a REST receiver is Apache NiFi using the
  **HandleHttpRequest** and **HandleHttpResponse** processors. This gives you
  a lightweight HTTP endpoint that can route, transform, or forward the JSON
  statistics without writing any custom code.
</Tip>

### Kafka Endpoint

| Configuration Key | Type | Description |
|---|---|---|
| `post_data_to_kafka` | `valueInt` | Set to `1` to enable the Kafka endpoint. |
| `post_data_to_kafka_extended` | `valueInt` | Set to `1` to send extended statistics to Kafka. |
| `kafka_brokers` | `valueStr` | Comma-separated list of Kafka broker addresses. |
| `kafka_topic` | `valueStr` | Kafka topic to publish messages to. |
| `kafka_saslmechanism` | `valueStr` | SASL mechanism (e.g. `PLAIN`, `SCRAM-SHA-256`). |
| `kafka_securityprotocol` | `valueStr` | Security protocol (e.g. `SASL_SSL`). |
| `kafka_trustcafile` | `valueStr` | Path to a CA bundle file for SSL connections. |

### AWS SNS

| Configuration Key | Type | Description |
|---|---|---|
| `post_data_to_awssns` | `valueInt` | Set to `1` to publish statistics to AWS SNS. |
| `post_data_to_awssns_extended` | `valueInt` | Set to `1` to send extended statistics to SNS. |
| `post_data_to_awssns_topic` | `valueStr` | ARN of the SNS topic to publish to. |

<Note>
  You can enable any combination of REST, Kafka, and AWS SNS simultaneously.
  Each endpoint can independently use the default or extended JSON format via
  its own `_extended` configuration key.
</Note>
